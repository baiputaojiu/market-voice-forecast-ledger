# 確定要件

## プロジェクト目的（Project Purpose）

YouTubeで公開されている対象者の発言を可能な範囲で網羅して蓄積し、その発言だけを根拠に、日経平均、TOPIX、S&P 500、XAU/USDがいつ上昇・横ばい・下降または転換すると述べているかを記録、比較、監査できるWindows向けローカルWebアプリを作る。

## 現在のスコープ（Current Scope）

### 分析主体

- 木野内栄治。旧入力の「木野内英二」は検索別名として保持する。
- 暁投資顧問。公式YouTubeチャンネルの発言を、話者別に分けず一つの組織主体として扱う。
- 江守哲。
- 大川智宏。旧入力の「大川智ひろ」は検索別名として保持する。

木野内栄治、江守哲、大川智宏は、本人の公式発信に限らず、ゲスト出演や他チャンネルへの出演も検索対象とする。暁投資顧問は公式チャンネルだけを対象にする。

### 対象資産

- 日経平均
- TOPIX
- S&P 500
- XAU/USD。円建て金ではなく米ドル建て金価格とする。

### 初期期間

初回バックフィルは直近3年とし、その後は日次同期と手動の「今すぐ同期」を提供する。

## 確定要件（Confirmed Requirements）

### 収集

- YouTube Data APIは動画発見とメタデータ取得にだけ使用できる。
- 公開検索可能な範囲で対象出演動画を最大限網羅する。
- 手動URL登録も提供する。
- Shorts、切り抜き、再投稿、重複動画も候補として収集するが、同じ発言は分析上1回だけ数える。
- 字幕が存在しない、または品質が不足する場合は、一時的に音声を取得しローカル文字起こしを行う。
- 動画本体は永続保存しない。音声は原則として文字起こしと必要な話者特徴抽出後に削除する。
- 分析用の動画日時はYouTube公開日時だけを保存する。収録日時は通常確認できないため保存・推定せず、内部の作成・取得日時を予想分析へ使わない。
- 全文文字起こしは非公開の内部データとしてリポジトリ外へ保存する。既定保存期限は文字起こし作成日から365日とし、30日、90日、180日、365日、無期限の設定と明示的な削除機能を設ける。

### 文字起こし、話者分離、話者割当

- 文字起こし、匿名話者への分離、実名への割当を、将来予想の分析とは独立した機能にする。
- ローカル音声AIでタイムコード付き文字起こしと匿名話者IDを作成する。
- ユーザーが確認した基準クリップから参照声の特徴を作り、各発話区間を参照声と直接照合して対象者、聞き手、保留へ割り当てる。単純な2群クラスタリングだけを本人判定に使わない。
- 確信度の低い割当は「保留」とし、予想分析から除外する。
- 聞き手の質問と要約は文脈として保存するが、対象者本人の予測根拠には使用しない。画面では「聞き手による要約」として本人発言とは分けて表示する。
- 予想分析へ渡す本人発言抽出物は、使用した話者割当結果のバージョンを参照する。
- 話者割当は現在値を保持し、修正時は変更前・変更後の構造化JSONと理由を追記専用監査ログへ保存する。依存する分析を「再分析が必要」にし、再分析成功まで旧結果を警告付きで表示する。
- 暁投資顧問の分析では個々の出演者に分けず、公式チャンネル内の組織主体として扱う。

### 予想分析

- OpenAI APIを直接組み込まず、Codex CLIへプロンプトと確定済み発言を渡して分析する。
- モデルは `gpt-5.6-sol`、reasoning effortは `max` を明示する。利用不能時に下位モデルへ自動変更しない。
- `codex exec` を読み取り専用、ephemeral、JSON Schema付きで実行し、Web検索、現在相場、一般知識による補強、shell、外部ツールを利用させない。分析runには外部ツール呼び出し件数を監査情報として保存する。
- 分析開始時に、指定日時点までの入力を変更不能なスナップショットとして固定する。
- 分析の基準日時は選択日のJST 23:59:59とする。
- 分析主体と基準日時の組を分析scopeとし、異なる基準日時の結果を共存させる。同じscopeの再分析は、検証成功後だけ現在結果を更新し、変更前後を監査する。
- YouTube公開日時が基準以前の動画だけを含める。ライブ配信は配信開始日時を公開日時として扱う。
- 内容上はより古い時期の発言と分かる場合でも、YouTube公開日時が基準後なら基準日時点の分析へ含めない。
- 現状説明・過去結果の分析と、将来予想を明確に分離する。
- 直接予想と、本人の発言だけから導いた推論予想を別フィールドに保存する。
- 基本予想と条件付き予想を別レイヤーに保存する。
- 条件付き予想はヒートマップへ条件付き印を表示し、条件文を必ず確認できるようにする。条件レイヤーを有効にした場合だけ主表示へ重ねる。
- 時期を特定できない発言は「時期不明」として保存し、レビューされるまで主ヒートマップから除外する。

### 対象指数への自動割当

- 「日本株」「米国株」「株式市場」など市場全般を表す発言は、本人発言と保存済み会話文脈だけから対象指数への割当候補を決める。
- 日本株全般は日経平均とTOPIX、米国株全般はS&P 500への割当候補とする。曖昧な「株式市場」は固定変換せず、文脈で対象市場を特定できる場合だけ割り当てる。
- 指数名の直接言及と市場全般からの推定割当を区別し、推定割当であることを画面に表示する。
- 自動割当には、元の対象表現、変換先指数、直接言及か推定割当か、変換理由、変換信頼度、元動画ID、発話タイムコードを保存する。
- 変換信頼度は `high`、`medium`、`low`、`unresolved` とする。Codexの自己評価とは別に、本人発言内の直接言及、周辺の本人発言、対象市場の競合、聞き手だけに存在する手掛かりをアプリ規則で検査する。
- Codex自己評価だけで信頼度を昇格させない。アプリ規則とCodex自己評価が異なる場合は低い側を自動採用上限とし、不一致を保存する。聞き手の発言だけを根拠に `high` または `medium` にしない。
- `low` と `unresolved` は主ヒートマップへ自動採用せず、ユーザーによる承認・修正・却下を必要とする。判断結果と理由は追記専用監査ログへ保存する。
- 発言の意味分類として、将来予想・現状分析・一般論を保存する。
- 対象解決の直接・推定と、予想形式の無条件・条件付きは別の軸で保存し、画面上の直接・条件付き・推定表示を生成する。
- 方向状態、条件、対象期間、ヒートマップ採用可否を保存する。採用可否の理由を監査可能にする。
- 例として、文脈上日本株を指す「8月、10月、12月に株式市場が底入れする可能性」は、日経平均とTOPIXへ推定割当した転換点として保存する。「2027年は米国の景気と株価が良い」は、S&P 500へ推定割当した上昇予想として保存する。金に関連する発言がなければXAU/USDは空欄とする。

### 予想分類と表示状態

- `+2`: 強い上昇
- `+1`: 上昇
- `0`: 横ばい
- `-1`: 下降
- `-2`: 強い下降
- `転換点`: 底入れ、天井打ちなど、方向へ無理に変換すべきでない転換
- `判断不能`

`判断不能`は関連発言があるが分類できない状態、`横ばい`は本人が横ばい相当を述べた状態、空欄は関連発言がない状態とし、相互に区別する。

相反する発言を平均して横ばいにしない。すべての履歴を保持し、より新しく、明示的で、時期が具体的な発言を現在見解として重く扱い、「見解変更」または「見解相違」を表示する。

### 期間

- 週間はJSTの月曜日から日曜日。
- 月間は暦月の初日から末日。
- 標準表示は12週間と12か月。期間列は横スクロールできる。
- 相対時期はYouTube公開日のJSTを基準に絶対日付範囲へ正規化し、`公開日基準` と使用日時を保存・表示する。収録日を推測しない。
- 「今週」は基準日を含む月～日、「来週」は次の月～日、「再来週」は2週後。
- 「今月」「来月」「再来月」は対応する暦月。
- 「半年後」は、より具体的な表現がなければ基準日の6か月後を含む暦月。
- 「第1週」のような語だけを表示せず、必ず絶対日付範囲を併記する。
- 「しばらく」「当面」「近いうち」など、防御可能な期間へ変換できない表現は「時期不明」とし、Codexに時期を創作させない。

### 表示

- 資産をプルダウンやタブで切り替えず、4資産を同じ画面で比較する。
- 4分析主体×4資産の16行を基本とし、列に期間を置く階層ヒートマップとする。
- 週・月の表示を切り替えられる。
- セルは方向、信頼度、根拠数を表示する。
- セル選択時は、必要最小限の短い根拠部分、タイムコード、動画、公開日時、相対期間が公開日基準であること、現在見解、変更履歴、反証、直接・推論・推定割当、条件を右側の証拠ドロワーへ表示する。全文文字起こしは通常画面へ表示しない。

### 進捗とバックグラウンド処理

- ブラウザを閉じても、Windowsへログイン中は収集、文字起こし、分析が継続する。
- 画面から一時停止、停止、再開、失敗箇所からの再試行を行える。
- 5～10分単位で再開可能なチェックポイントを保存し、完了済み区間と変更不能な段階結果を再利用する。
- 分析開始前に決定的なバッチmanifestを作り、実際の完了作業単位だけで進捗率を計算する。
- 処理順序は、音声取得、分割文字起こし、話者割当、本人発言抽出、Codex分析、指数への自動割当、ヒートマップ集計とする。話者割当結果と予想分析結果は別データとして保存する。
- 進捗表示は、動画取得、文字起こしの各分割、話者割当、Codex分析、自動割当、ヒートマップ更新の実完了数を段階別に示す。
- 処理数、現在の分析主体・資産・バッチ、経過時間、最終イベントを表示する。
- 残り時間は推定しない。
- 失敗時は最後の完了単位で停止し、成功済みの変更不能なバッチ結果を再試行に利用する。

### ローカル構成

- Windows上で動くローカルWebアプリとする。
- UIはReact、TypeScript、Vite。
- ローカルAPIはFastAPI。
- 永続メタデータはSQLite。
- Windowsログイン時にバックグラウンドワーカーを起動する。
- HTTPは `127.0.0.1` だけへbindする。
- YouTube APIキーはWindows側で保護し、画面、ログ、リポジトリへ出さない。
- 音声処理エンジンをアダプター境界で隔離し、Windowsネイティブ実装を第一候補、必要時にWSL2実装へ交換可能にする。

### 想定端末

- Windows 11 Home
- Intel Core i7-8550U、4コア8スレッド
- Intel UHD Graphics 620
- RAM 15.9GB
- NVIDIA GPUなし

処理速度より精度を優先し、夜間・バックグラウンドで時間をかける運用を許容する。

## 分析の情報境界（Analysis Information Boundary）

Codexへ渡せるのは、基準日時点までに保存された対象者の発言本文、発言タイムコード、動画タイトル、チャンネル、公開日時などの出典メタデータだけとする。次を予想根拠へ使用しない。

- Web検索結果
- 現在または過去の市場価格データ
- ニュースや経済指標
- Codex自身の一般知識
- 対象者以外の見解

CodexはアプリDBへ直接書き込まない。読み取り専用の入力領域から分析し、JSON Schemaに従った出力をアプリが検証して保存する。

## MVP外の将来機能（Future Features Outside MVP）

- 実際の価格データを使った予想成績評価。
- 予想と実績の一致率、時期別・主体別の評価。
- 対象者や対象資産の追加。
- 複数ユーザーまたは複数人同時開発に対応した運用。
