# 確定要件

## プロジェクト目的（Project Purpose）

YouTubeで公開されている分析主体の採用対象発言を可能な範囲で網羅して蓄積し、その発言だけを根拠に、日経平均、TOPIX、S&P 500、XAU/USDがいつ上昇・横ばい・下降または転換すると述べているかを記録、比較、監査できるWindows向けローカルWebアプリを作る。

## 現在のスコープ（Current Scope）

### 分析主体

- 木野内栄治。旧入力の「木野内英二」は検索別名として保持する。
- 暁投資顧問。公式YouTubeチャンネルID `UCOfzLmXpI3qmZfV7_Cs1sYA` の動画内にある全発言を、社内出演者、外部ゲスト、聞き手で分けず、一つの組織主体の発言として扱う。
- 江守哲。ユーザー指定の「江守哲の米国株投資チャンネル」1チャンネルだけを対象とする。この名称は確認用の表示名とし、YouTubeチャンネルID `UCVXka7buS_WptsAzSE0LcKg` を正本として固定する。
- 大川智宏。旧入力の「大川智ひろ」は検索別名として保持する。

木野内栄治と大川智宏は、本人の公式発信に限らず、ゲスト出演や他チャンネルへの出演も検索・分析対象とする。江守哲は固定した1チャンネルだけ、暁投資顧問は公式チャンネルだけを対象とする。暁投資顧問は出演者別・役割別に分けず、公式チャンネル内の全発言を組織として分析する。

### 対象資産

- 日経平均
- TOPIX
- S&P 500
- XAU/USD。円建て金ではなく米ドル建て金価格とする。

### 初期期間

初回バックフィルは直近3年とし、その後は日次同期と手動の「今すぐ同期」を提供する。

## 確定要件（Confirmed Requirements）

### 収集

- YouTube Data APIは動画発見とメタデータ取得にだけ使用できる。
- 公開検索可能な範囲で対象出演動画を最大限網羅する。
- 手動URL登録も提供する。
- 手動URL登録は分析主体ごとのチャンネル範囲を迂回しない。動画URLから正規のYouTubeチャンネルIDを解決した後に対象可否を判定し、チャンネル表示名や入力URL文字列は正本にしない。
- 木野内栄治と大川智宏はチャンネルを限定せず、対象者本人の出演を確認できた動画を分析候補にする。
- 江守哲の自動検索は、ユーザーが指定した固定チャンネルIDのチャンネル内だけで行う。固定IDと動画のチャンネルIDが完全一致した場合だけ収集・分析候補にする。他チャンネルの出演動画は、手動URLで登録されてもメタデータを `channel_out_of_scope` として保存できるだけで、音声取得、文字起こし、予想分析、ヒートマップへ進めない。動画単位の例外承認では迂回できず、対象チャンネル方針自体の変更が必要である。
- 江守哲の対象チャンネルは、表示名「江守哲の米国株投資チャンネル」、正本ID `UCVXka7buS_WptsAzSE0LcKg` としてユーザー確認済みである。このIDと動画の正規チャンネルIDが完全一致した場合だけ収集・分析候補にする。
- 暁投資顧問は正本ID `UCOfzLmXpI3qmZfV7_Cs1sYA` の公式チャンネル内だけを自動検索し、その動画だけを収集・分析候補にして、組織として扱う。
- 元動画、Shorts、切り抜き、再投稿を重複判定・統合・除外しない。それぞれを独立した動画、発言、根拠として保存し、分析・集計する。後から公開された切り抜きが新しい発言として現在見解へ影響することと、同内容によって根拠数が増えることを許容する。
- 字幕が存在しない、または品質が不足する場合は、一時的に音声を取得しローカル文字起こしを行う。
- 動画本体は永続保存しない。音声はアプリ専用の一時音声フォルダーだけへ保存し、原則として文字起こしと必要な話者特徴抽出後に削除する。自動削除前に解決済み絶対パスが専用フォルダー配下であることを検査し、範囲外なら削除を拒否して記録する。
- 分析用の動画日時はYouTube公開日時だけを保存する。収録日時は通常確認できないため保存・推定せず、内部の作成・取得日時を予想分析へ使わない。
- 全文文字起こしは非公開の内部データとしてリポジトリ外へ保存する。既定保存期限は文字起こし作成日から365日とし、30日、90日、180日、365日、無期限の設定と明示的な削除機能を設ける。

### 文字起こし、話者分離、話者割当

- 文字起こし、匿名話者への分離、実名への割当を、将来予想の分析とは独立した機能にする。
- ローカル音声AIでタイムコード付き文字起こしと匿名話者IDを作成する。
- ユーザーが確認した基準クリップから参照声の特徴を作り、各発話区間を参照声と直接照合して対象者、聞き手、保留へ割り当てる。単純な2群クラスタリングだけを本人判定に使わない。MVPでは音声モデルを1種類に固定し、モデル名、モデルバージョン、生スコア、判定に使った閾値設定バージョンを保存する。共通の0～1正規化と複数モデル対応は行わない。
- 確信度の低い割当は「保留」とし、予想分析から除外する。
- 木野内栄治、江守哲、大川智宏については、聞き手の質問と要約を文脈として保存するが、対象者本人の予測根拠には使用しない。画面では「聞き手による要約」として本人発言とは分けて表示する。
- 予想分析へ渡す主体別分析入力の抽出物は、使用した話者割当結果または暁投資顧問の組織割当結果のバージョンを参照する。
- 話者割当は現在値を保持し、修正時は変更前・変更後の構造化JSONと理由を追記専用監査ログへ保存する。依存する分析を「再分析が必要」にし、再分析成功まで旧結果を警告付きで表示する。
- 暁投資顧問の分析では、正本チャンネルIDと一致した動画内の全発話区間を、社内出演者、外部ゲスト、聞き手へ分けず、組織主体「暁投資顧問」の分析入力にする。この主体だけは聞き手除外規則の例外とする。

### 予想分析

- OpenAI APIを直接組み込まず、Codex CLIへプロンプトと確定済み発言を渡して分析する。
- モデルは `gpt-5.6-sol`、reasoning effortは `max` を明示する。利用不能時に下位モデルへ自動変更しない。
- `codex exec` を読み取り専用、ephemeral、JSON Schema付きで実行し、Web検索、現在相場、一般知識による補強、shell、外部ツールを利用させない。分析runには外部ツール呼び出し件数を監査情報として保存する。
- 分析開始時に、指定日時点までの入力を変更不能なスナップショットとして固定する。
- 分析の基準日はユーザーが選択したJST暦日とする。内部判定では、その翌日JST 0時をUTCへ変換した排他的上限を使い、`published_at` がその上限未満の動画を対象にする。これは選択日JST 23:59:59までという画面上の意味を、小数秒を取りこぼさず表現する。
- 分析主体と基準日時の組を分析scopeとし、異なる基準日時の結果を共存させる。同じscopeの再分析は、検証成功後だけ現在結果を更新し、変更前後を監査する。
- 監査ログ、分析run、レビュー履歴は追記専用とし、サービス層とSQLiteの両方で更新・削除を拒否する。正確な分析入力本文は、保持期限による本文のNULL化と削除日時設定だけを限定的に許可する。
- YouTube公開日時が基準以前の動画だけを含める。ライブ配信は配信開始日時を公開日時として扱う。
- 内容上はより古い時期の発言と分かる場合でも、YouTube公開日時が基準後なら基準日時点の分析へ含めない。
- 発言を `将来予想`、`現状分析`、`過去結果の分析`、`一般論` の4種類へ分け、将来予想以外を主ヒートマップへ自動採用しない。
- `直接予想` と、分析主体として採用された発言だけから導いた `発言内推論` を別フィールドに保存する。これは対象指数の `直接言及` と `推定割当` とは別の軸にする。
- 1つの分析済み発言へ複数の分析対象発話区間を順序付きで結び付けられるようにする。個人主体では本人割当区間だけ、暁投資顧問では適合済み公式チャンネルの組織割当区間だけを許可する。短い根拠は各発話区間の保存済み文字起こしに存在する連続部分だけを許可し、Codexが作った自由な要約文を根拠として保存しない。
- 基本予想と条件付き予想を別レイヤーに保存する。
- 条件付き予想はヒートマップへ条件付き印を表示し、条件文を必ず確認できるようにする。条件レイヤーを有効にした場合だけ主表示へ重ねる。
- 時期を特定できない発言は「時期不明」として保存し、ユーザーの承認または却下と理由を監査する。承認後は、週表示・月表示の両方に設ける通常期間とは別の「時期不明」列へ表示できる。未承認の時期不明予想は主ヒートマップへ採用しない。

### 対象指数への自動割当

- 「日本株」「米国株」「株式市場」など市場全般を表す発言は、分析主体として採用された発言と許可済み会話文脈だけから対象指数への割当候補を決める。個人主体では本人発言を根拠とし、暁投資顧問では適合済み公式チャンネルの組織割当発言を根拠とする。
- 日本株全般は日経平均とTOPIX、米国株全般はS&P 500への割当候補とする。曖昧な「株式市場」は固定変換せず、文脈で対象市場を特定できる場合だけ割り当てる。
- 指数名の直接言及と市場全般からの推定割当を区別し、推定割当であることを画面に表示する。
- 自動割当には、元の対象表現、変換先指数、直接言及か推定割当か、変換理由、変換信頼度、元動画ID、発話タイムコードを保存する。
- 変換信頼度は `high`、`medium`、`low`、`unresolved` とする。Codexの自己評価とは別に、分析主体の採用対象発言内の直接言及、周辺の採用対象発言、対象市場の競合をアプリ規則で検査する。個人主体では、聞き手だけに存在する手掛かりも検査する。
- Codex自己評価だけで信頼度を昇格させない。アプリ規則とCodex自己評価が異なる場合は低い側を自動採用上限とし、不一致を保存する。個人主体では聞き手の発言だけを根拠に `high` または `medium` にしない。暁投資顧問では、適合済み公式チャンネルの全発言を組織発言として扱う例外を優先する。
- `low` と `unresolved` は主ヒートマップへ自動採用せず、ユーザーによる承認・修正・却下を必要とする。判断結果と理由は追記専用監査ログへ保存する。
- 発言の意味分類として、将来予想・現状分析・過去結果の分析・一般論を保存する。
- 対象解決の直接・推定と、予想形式の無条件・条件付きは別の軸で保存し、画面上の直接・条件付き・推定表示を生成する。
- 方向状態、条件、対象期間、ヒートマップ採用可否を保存する。採用可否の理由を監査可能にする。
- 例として、文脈上日本株を指す「8月、10月、12月に株式市場が底入れする可能性」は、日経平均とTOPIXへ推定割当した転換点として保存する。「2027年は米国の景気と株価が良い」は、S&P 500へ推定割当した上昇予想として保存する。金に関連する発言がなければXAU/USDは空欄とする。

### 予想分類と表示状態

- `+2`: 強い上昇
- `+1`: 上昇
- `0`: 横ばい
- `-1`: 下降
- `-2`: 強い下降
- `転換点`: 底入れ、天井打ちなど、方向へ無理に変換すべきでない転換
- `判断不能`

`判断不能`は関連発言があるが分類できない状態、`横ばい`は分析主体の採用対象発言に横ばい相当の表現がある状態、空欄は関連発言がない状態とし、相互に区別する。

相反する発言を平均して横ばいにしない。同じ分析主体・資産・比較可能な対象期間・条件レイヤーに属する採用可能な予想は、UTCへ正規化したYouTube公開日時ごとにまとめる。`+1`・`+2`を上昇系、`-1`・`-2`を下降系とし、同じ公開日時に両方があれば、同一動画か別動画か、直接予想か発言内推論か、直接言及か推定割当か、期間具体性にかかわらず、両方向を持つ「見解相違」とする。最新公開日時群の上昇系・下降系が、いずれかの古い公開日時群の方向と逆なら「見解変更」とし、途中に同方向の再投稿があっても変更履歴を失わない。最新群を現在見解、古い群を履歴・反証として保持する。同じ公開日時群に逆方向がない場合だけ、直接予想、次に期間具体性を代表表示の選択に使えるが、独立根拠は削除しない。横ばい、転換点、判断不能、空欄は独立状態とし、自動的な見解相違・見解変更へ変換しない。条件付き予想は無条件予想との競合判定へ混ぜない。

### 期間

- 週間はJSTの月曜日から日曜日。
- 月間は暦月の初日から末日。
- DBへ保存する日時と内部の日時比較はUTCに統一する。画面表示、日付指定、相対期間、週・月の暦日判定には固定JST（UTC+9）を使い、`ZoneInfo`、IANA timezone database、`tzdata`へ依存しない。
- 「何月第1週」は、その月の1日を含む月曜日から日曜日とする。月をまたいでも週を分割せず、絶対日付範囲を表示する。
- 標準表示は12週間と12か月。期間列は横スクロールできる。
- 相対時期はYouTube公開日のJSTを基準に絶対日付範囲へ正規化し、`公開日基準` と使用日時を保存・表示する。採用対象発言で明示された年月日・期間は `明示期間` として保存し、公開日から導いた期間と区別する。収録日を推測しない。
- 「今週」は基準日を含む月～日、「来週」は次の月～日、「再来週」は2週後。
- 「今月」「来月」「再来月」は対応する暦月。
- 「半年後」は、より具体的な表現がなければ基準日の6か月後を含む暦月。
- 「第1週」のような語だけを表示せず、必ず絶対日付範囲を併記する。
- 「しばらく」「当面」「近いうち」など、防御可能な期間へ変換できない表現は「時期不明」とし、Codexに時期を創作させない。

### 表示

- 資産をプルダウンやタブで切り替えず、4資産を同じ画面で比較する。
- 4分析主体×4資産の16行を基本とし、列に期間を置く階層ヒートマップとする。
- 週・月の表示を切り替えられる。
- セルは方向、信頼度、根拠数を表示する。
- 時期不明の承認済み予想は通常の週・月列へ割り当てず、「時期不明」専用列へ表示する。同じ動画内の相反予想は横ばいにせず「見解相違」セルとして両方向を表示する。
- セル選択時は、必要最小限の短い根拠部分、タイムコード、動画、公開日時、相対期間が公開日基準であること、現在見解、変更履歴、反証、直接・推論・推定割当、条件を右側の証拠ドロワーへ表示する。全文文字起こしは通常画面へ表示しない。

### 進捗とバックグラウンド処理

- ブラウザを閉じても、Windowsへログイン中は収集、文字起こし、分析が継続する。
- 画面から一時停止、停止、再開、失敗箇所からの再試行を行える。
- 5～10分単位で再開可能なチェックポイントを保存し、完了済み区間と変更不能な段階結果を再利用する。
- 再試行は長い工程全体ではなく5～10分相当の作業unit単位とする。中断中のunitと再試行対象の失敗unitを `pending` へ戻し、そのunitを先頭から実行する。途中結果は正式成果物として採用しない。
- 完了済みunitは、入力hash、成果物hash、モデル・設定・契約versionが一致する場合だけ再利用する。出力検証とunitの `success` 確定は同一transactionで行う。
- 分析開始前に決定的なバッチmanifestを作り、実際の完了作業単位だけで進捗率を計算する。
- 処理順序は、動画情報取得・チャンネル判定、音声取得、分割文字起こし、話者割当、主体別分析入力抽出、Codex分析、指数への自動割当、ヒートマップ集計とする。話者割当結果と予想分析結果は別データとして保存する。
- 進捗表示は、動画情報取得・チャンネル判定、音声取得、文字起こしの各分割、話者割当、主体別分析入力抽出、Codex分析、自動割当、ヒートマップ更新の実完了数を段階別に示す。
- 処理数、現在の分析主体・資産・バッチ、経過時間、最終イベントを表示する。
- 残り時間は推定しない。
- 失敗時は最後の完了unitで停止し、検証済みの `success` unitだけを再試行に利用する。最終反映unit以外の全upstream unitと後段検証が完了した場合だけ、最終反映unitが現在予想、run受理event、監査event、ヒートマップ、自身の `success`、jobの `succeeded` を一つのtransactionで更新する。途中または失敗したrunから主ヒートマップを部分更新しない。

### ローカル構成

- Windows上で動くローカルWebアプリとする。
- UIはReact、TypeScript、Vite。
- ローカルAPIはFastAPI。
- 永続メタデータはSQLite。
- Windowsログイン時にバックグラウンドワーカーを起動する。
- HTTPは `127.0.0.1` だけへbindする。
- MVPではローカルトークン、`Origin`検査、Windowsアカウント認証を設けず、`127.0.0.1`へのbind限定をAPIアクセス境界とする。
- このMVP境界は信頼できる単独利用PCを前提とし、同じPC上の別プロセスやブラウザから到達される可能性を防がない。loopback bindを認証や機密性の境界とみなさず、状態変更APIへGETを使わない。追加認証と送信元検査は将来機能として扱う。
- YouTube APIキーはWindows側で保護し、画面、ログ、リポジトリへ出さない。
- 音声処理エンジンをアダプター境界で隔離し、Windowsネイティブ実装を第一候補、必要時にWSL2実装へ交換可能にする。

### 想定端末

- Windows 11 Home
- Intel Core i7-8550U、4コア8スレッド
- Intel UHD Graphics 620
- RAM 15.9GB
- NVIDIA GPUなし

処理速度より精度を優先し、夜間・バックグラウンドで時間をかける運用を許容する。

## 分析の情報境界（Analysis Information Boundary）

Codexへ渡せるのは、基準日時点までに保存され、主体別規則で採用された発言本文、発言タイムコード、動画タイトル、チャンネル、公開日時などの出典メタデータだけとする。個人主体では本人割当発言だけ、暁投資顧問では適合済み公式チャンネルの組織割当発言だけを入力する。次を予想根拠へ使用しない。

- Web検索結果
- 現在または過去の市場価格データ
- ニュースや経済指標
- Codex自身の一般知識
- 主体別規則で採用対象外となった発言や見解

CodexはアプリDBへ直接書き込まない。読み取り専用の入力領域から分析し、JSON Schemaに従った出力をアプリが検証して保存する。

- 複数ユーザーまたは複数人同時開発に対応した運用。
