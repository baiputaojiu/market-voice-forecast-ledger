# 重要な決定と理由

## 記録規則（Recording Rules）

- IDは変更しない。
- 状態は「採用」「置換済み」「却下」のいずれかとする。
- 現在の要件は `requirements.md` を正本とし、このファイルには判断理由と重要な比較案を残す。
- 小さな実装詳細や日々の進捗は記録しない。

## 採用中の決定（Accepted Decisions）

### DEC-001: ローカルWebアプリ

- 状態: 採用
- 決定: React＋TypeScript＋Vite、FastAPI、SQLite、Windowsバックグラウンドワーカーを採用し、`127.0.0.1` だけへ公開する。
- 理由: デスクトップ向けの密度ある比較UI、長時間バックグラウンド処理、ローカルデータ保護を両立できる。
- 比較案: ネイティブデスクトップアプリ、クラウドWebアプリ。
- 却下理由: ネイティブUIは初期開発コストが高く、クラウドは音声・全文文字起こしの公開境界と運用費が増える。

### DEC-002: 予想分析はCodex CLI

- 状態: 採用
- 決定: OpenAI APIをアプリへ直接組み込まず、構造化出力付き `codex exec` を使う。
- 理由: ユーザーのCodex認証と最上位モデルを利用し、APIキー管理を増やさない。
- 影響: アプリはCodex CLIの存在とログイン状態を検査し、モデル利用不能時は停止する。

### DEC-003: 最上位モデルを固定

- 状態: 採用
- 決定: `gpt-5.6-sol` とreasoning effort `max` を明示し、下位モデルへ自動フォールバックしない。
- 理由: 分析品質を最優先し、モデル差による分析結果の不透明な変化を防ぐ。

### DEC-004: 分析根拠を保存済み発言に限定

- 状態: 採用
- 決定: Web検索、現在相場、価格履歴、ニュース、Codexの一般知識を予想の補強に使わない。
- 理由: 「誰がいつ何を予想したか」を監査可能にし、外部知識が混ざった独自予想へ変質することを防ぐ。

### DEC-005: 話者処理と予想分析を分離

- 状態: 採用
- 決定: 文字起こし、話者分離、話者割当を、将来予想の抽出・集約から独立させる。
- 理由: 話者割当の修正履歴と予想分析の再現性を保ち、低信頼話者を分析から除外できる。

### DEC-006: 暁投資顧問を一分析主体とする

- 状態: 採用
- 決定: 暁投資顧問の公式チャンネルだけを対象にし、出演者別に分けず組織として分析する。
- 理由: ユーザーが組織見解として比較することを選択した。

### DEC-007: 個人3名はゲスト出演も収集

- 状態: 採用
- 決定: 木野内栄治、江守哲、大川智宏は他チャンネルへの出演を含める。
- 理由: 本人の市場見通しを可能な範囲で網羅するため。

### DEC-008: 初回収集は直近3年

- 状態: 採用
- 決定: 直近3年をバックフィルし、その後は日次同期と手動同期を行う。
- 理由: 網羅性とCPUのみで行う初期処理時間の均衡を取る。

### DEC-009: 一時音声取得とローカル文字起こし

- 状態: 採用
- 決定: 字幕不足時は個人利用の分析目的で音声を一時取得し、ローカルで文字起こし後に原則削除する。
- 理由: YouTube Data APIだけでは他者動画の全文字幕を安定取得できないため。

### DEC-010: 予想を6区分する

- 状態: 採用
- 決定: 強い上昇、上昇、横ばい、下降、強い下降、判断不能を使う。
- 理由: 単純な上昇・下降より強度と不確実性を保持できる。

### DEC-011: 直接・推論・条件付き・現状説明を分離

- 状態: 採用
- 決定: 直接予想、発言内推論、条件付き予想、現状・過去分析を別フィールドにする。
- 理由: 対象者の明示見解とCodexの分類判断を混同せず、将来予想以外を主ヒートマップへ入れないため。

### DEC-012: 4資産を同一画面で比較

- 状態: 採用
- 決定: 分析主体×4資産の16行ヒートマップを使い、資産のプルダウンやタブ切替を設けない。
- 理由: 資産間、主体間、期間間の比較を一つの視野で行うため。

### DEC-013: 期間を絶対日付範囲へ正規化

- 状態: 採用
- 決定: 週は月～日、月は暦月とし、相対表現を公開日のJSTから絶対範囲へ変換する。曖昧表現は時期不明とする。
- 理由: 別日時点の分析を比較可能にし、Codexによる時期の創作を防ぐ。

### DEC-014: 相反見解を平均しない

- 状態: 採用
- 決定: 新しさ、明示性、時期の具体性で現在見解を選び、相反履歴は見解変更・見解相違として残す。
- 理由: 上昇と下降を機械的に横ばいへすることは、発言の意味を失わせるため。

### DEC-015: 実作業単位だけで進捗表示

- 状態: 採用
- 決定: 決定的なバッチmanifestから完了数を算出し、残り時間は表示しない。
- 理由: AI処理時間は変動が大きく、擬似的な進捗率やETAは誤解を招くため。

### DEC-016: 公開GitHub＋更新型状態文書＋2スキル

- 状態: 採用
- 決定: 4つの状態文書を更新し、保存と再開を別スキルにする。通常保存ごとに新規状態ファイルを作らない。
- 理由: 情報の責務を分け、書き込みを伴う保存と読み取り中心の再開の安全境界を明確にする。

### DEC-017: `AGENTS.md` は短い共通規則だけ

- 状態: 採用
- 決定: 長い進捗、履歴、保存手順を置かず、状態文書とスキルへの案内だけを記載する。
- 理由: 毎回読み込む文脈を小さくし、変化する情報を適切な正本へ分離するため。

### DEC-018: 実データをリポジトリ外へ保存

- 状態: 採用
- 決定: `%LOCALAPPDATA%\MarketVoiceForecastLedger\` を既定保存先にする。
- 理由: 大容量データや権利確認が必要なデータの誤commitを構造的に防ぐため。

### DEC-019: PowerShell実行ファイルはASCII互換に保つ

- 状態: 採用
- 決定: Windows PowerShell 5.1でもBOMなしUTF-8の解釈差が起きないよう、`.ps1`の実行文字列はASCII互換にし、日本語文書の構造検査には英語併記の安定した見出しを使う。
- 理由: PCを切り替えたときの既定文字コード差で、検査や保存・再開処理が構文エラーになることを防ぐため。

### DEC-020: 初回公開先とbranch

- 状態: 採用
- 決定: `baiputaojiu/market-voice-forecast-ledger`を公開GitHubリポジトリとして作成し、既定branchを`main`とする。初回公開時点ではライセンスを設定しない。
- 理由: プロジェクト名とローカルディレクトリ名を一致させ、単独PC切替運用では単純な`main`運用を採用するため。ライセンスは再利用条件を別途判断してから追加する。
