# 重要な決定と理由

## 記録規則（Recording Rules）

- IDは変更しない。
- 状態は「採用」「置換済み」「却下」のいずれかとする。
- 現在の要件は `requirements.md` を正本とし、このファイルには判断理由と重要な比較案を残す。
- 小さな実装詳細や日々の進捗は記録しない。

## 採用中の決定（Accepted Decisions）

### DEC-001: ローカルWebアプリ

- 状態: 採用
- 決定: React＋TypeScript＋Vite、FastAPI、SQLite、Windowsバックグラウンドワーカーを採用し、`127.0.0.1` だけへ公開する。
- 理由: デスクトップ向けの密度ある比較UI、長時間バックグラウンド処理、ローカルデータ保護を両立できる。
- 比較案: ネイティブデスクトップアプリ、クラウドWebアプリ。
- 却下理由: ネイティブUIは初期開発コストが高く、クラウドは音声・全文文字起こしの公開境界と運用費が増える。

### DEC-002: 予想分析はCodex CLI

- 状態: 採用
- 決定: OpenAI APIをアプリへ直接組み込まず、構造化出力付き `codex exec` を使う。
- 理由: ユーザーのCodex認証と最上位モデルを利用し、APIキー管理を増やさない。
- 影響: アプリはCodex CLIの存在とログイン状態を検査し、モデル利用不能時は停止する。

### DEC-003: 最上位モデルを固定

- 状態: 採用
- 決定: `gpt-5.6-sol` とreasoning effort `max` を明示し、下位モデルへ自動フォールバックしない。
- 理由: 分析品質を最優先し、モデル差による分析結果の不透明な変化を防ぐ。

### DEC-004: 分析根拠を保存済み発言に限定

- 状態: 採用
- 決定: Web検索、現在相場、価格履歴、ニュース、Codexの一般知識を予想の補強に使わない。分析runではshellと外部ツールも無効化し、外部ツール呼び出し件数を監査する。
- 理由: 「誰がいつ何を予想したか」を監査可能にし、外部知識が混ざった独自予想へ変質することを防ぐ。ユーザー実施のスモールテストでは外部ツール呼び出し0件を確認できた。

### DEC-005: 話者処理と予想分析を分離

- 状態: 採用
- 決定: 文字起こし、話者分離、話者割当を、将来予想の抽出・集約から独立させる。
- 理由: 話者割当の修正履歴と予想分析の再現性を保ち、低信頼話者を分析から除外できる。

### DEC-006: 暁投資顧問を一分析主体とする

- 状態: 採用
- 決定: 暁投資顧問の公式チャンネルだけを対象にし、出演者別に分けず組織として分析する。
- 理由: ユーザーが組織見解として比較することを選択した。

### DEC-007: 木野内栄治と大川智宏はゲスト出演も収集

- 状態: 採用
- 決定: 木野内栄治と大川智宏は、公式発信に限定せず他チャンネルへのゲスト出演も検索・分析対象に含める。
- 理由: 本人の市場見通しを可能な範囲で網羅するため。

### DEC-008: 初回収集は直近3年

- 状態: 採用
- 決定: 直近3年をバックフィルし、その後は日次同期と手動同期を行う。
- 理由: 網羅性とCPUのみで行う初期処理時間の均衡を取る。

### DEC-009: 一時音声取得とローカル文字起こし

- 状態: 採用
- 決定: 字幕不足時は個人利用の分析目的で音声を一時取得し、ローカルで文字起こし後に原則削除する。
- 理由: YouTube Data APIだけでは他者動画の全文字幕を安定取得できないため。

### DEC-010: 方向と転換点を分けて分類する

- 状態: 採用
- 決定: 強い上昇、上昇、横ばい、下降、強い下降、転換点、判断不能を使う。関連発言なしは空欄とし、分類状態へ含めない。
- 理由: 方向の強度を保持しながら、「底入れ」など方向そのものではない見通しと、判断不能、明示的な横ばい、証拠なしを混同しないため。

### DEC-011: 直接・推論・条件付き・現状説明を分離

- 状態: 採用
- 決定: 直接予想、発言内推論、条件付き予想、現状・過去分析を別フィールドにする。
- 理由: 対象者の明示見解とCodexの分類判断を混同せず、将来予想以外を主ヒートマップへ入れないため。

### DEC-012: 4資産を同一画面で比較

- 状態: 採用
- 決定: 分析主体×4資産の16行ヒートマップを使い、資産のプルダウンやタブ切替を設けない。
- 理由: 資産間、主体間、期間間の比較を一つの視野で行うため。

### DEC-013: 期間を絶対日付範囲へ正規化

- 状態: 採用
- 決定: 週は月～日、月は暦月とし、相対表現をYouTube公開日のJSTから絶対範囲へ変換する。結果へ公開日基準と使用日時を保存・表示し、曖昧表現は時期不明とする。
- 理由: 収録日は通常公開されず、防御可能な共通基準にできない。公開日なら別PC・再分析でも同じ期間を再現でき、Codexによる収録日の推測を防げる。
- 影響: 収録から公開まで間がある動画では本人の意図した相対期間とずれる可能性があるため、公開日基準であることを画面に明示し、手動修正は監査する。

### DEC-014: 相反見解を平均しない

- 状態: 採用
- 決定: 新しさ、明示性、時期の具体性で現在見解を選び、相反履歴は見解変更・見解相違として残す。
- 理由: 上昇と下降を機械的に横ばいへすることは、発言の意味を失わせるため。

### DEC-015: 実作業単位だけで進捗表示

- 状態: 採用
- 決定: 決定的なバッチmanifestから完了数を算出し、残り時間は表示しない。
- 理由: AI処理時間は変動が大きく、擬似的な進捗率やETAは誤解を招くため。

### DEC-016: 公開GitHub＋更新型状態文書＋2スキル

- 状態: 採用
- 決定: 4つの状態文書を更新し、保存と再開を別スキルにする。通常保存ごとに新規状態ファイルを作らない。
- 理由: 情報の責務を分け、書き込みを伴う保存と読み取り中心の再開の安全境界を明確にする。

### DEC-017: `AGENTS.md` は短い共通規則だけ

- 状態: 採用
- 決定: 長い進捗、履歴、保存手順を置かず、状態文書とスキルへの案内だけを記載する。
- 理由: 毎回読み込む文脈を小さくし、変化する情報を適切な正本へ分離するため。

### DEC-018: 実データをリポジトリ外へ保存

- 状態: 採用
- 決定: `%LOCALAPPDATA%\MarketVoiceForecastLedger\` を既定保存先にする。
- 理由: 大容量データや権利確認が必要なデータの誤commitを構造的に防ぐため。

### DEC-019: PowerShell実行ファイルはASCII互換に保つ

- 状態: 採用
- 決定: Windows PowerShell 5.1でもBOMなしUTF-8の解釈差が起きないよう、`.ps1`の実行文字列はASCII互換にし、日本語文書の構造検査には英語併記の安定した見出しを使う。
- 理由: PCを切り替えたときの既定文字コード差で、検査や保存・再開処理が構文エラーになることを防ぐため。

### DEC-020: 初回公開先とbranch

- 状態: 採用
- 決定: `baiputaojiu/market-voice-forecast-ledger`を公開GitHubリポジトリとして作成し、既定branchを`main`とする。初回公開時点ではライセンスを設定しない。
- 理由: プロジェクト名とローカルディレクトリ名を一致させ、単独PC切替運用では単純な`main`運用を採用するため。ライセンスは再利用条件を別途判断してから追加する。

### DEC-021: 参照声との直接照合を話者割当の主方式にする

- 状態: 採用
- 決定: 短い確認済み基準クリップから参照声を作り、各発話区間を対象者、聞き手、保留へ直接割り当てる。匿名話者クラスタリングは補助にできるが、単純な2群クラスタリングだけで本人を判定しない。
- 理由: ユーザー実施の39分39秒・722区間のスモールテストでは、単純な2群クラスタリングが失敗した一方、参照声との直接照合で対象者653区間、聞き手55区間、保留14区間へ分離できた。

### DEC-022: 本人発言だけを予想根拠にする

- 状態: 採用
- 決定: 聞き手の質問・要約は会話文脈として保存するが、本人の予想根拠には使わず、「聞き手による要約」として別表示する。予想分析へは本人に割り当てた発言だけを投入する。
- 理由: 聞き手の解釈を本人の見解として誤帰属せず、会話の読解に必要な文脈は失わないため。

### DEC-023: 市場全般の表現を監査可能な推定割当へ変換する

- 状態: 採用
- 決定: 日本株全般は日経平均とTOPIX、米国株全般はS&P 500への候補とし、保存済み文脈で対象市場を特定できる場合だけ推定割当する。直接言及と推定割当を分け、元表現、変換先、理由、信頼度、出典を保存する。
- 理由: 本人が指数名を使わない市場見通しも比較対象へ反映しつつ、Codexが行った対象解決を本人の直接発言と誤認させないため。

### DEC-024: 転換点・判断不能・横ばい・空欄を混同しない

- 状態: 採用
- 決定: 底入れや天井打ちは独立した転換点とし、上昇または下降へ強制変換しない。判断不能、横ばい、関連発言なしの空欄も別状態として扱う。
- 理由: 発言が示す市場局面と、方向、分類不能、証拠なしは意味が異なり、単一の中立値へ畳むと監査性を失うため。

### DEC-025: 条件付き予想を独立レイヤーにする

- 状態: 採用
- 決定: 無条件予想と条件付き予想を別軸で保存し、ヒートマップでは条件付き印を付け、条件文を常に確認可能にする。
- 理由: 条件成立を確認していない予想を基本見解と同じ確度で表示しないため。

### DEC-026: 分析用の動画日時を公開日時だけにする

- 状態: 採用
- 決定: 分析用にはYouTube公開日時だけを保存する。収録日時は保存・推定せず、システム作成・取得日時は内部監査にだけ使い、分析へ使わない。
- 理由: 収録日時は通常公開されず、システム取得日時はユーザーの実行都合で変わる。公開日時だけが公開情報として一貫して取得でき、日付指定分析を再現できる。
- 置換した案: 収録日、公開日、取得日を別々に保存し、相対時期を収録日基準にする方式。利用できない収録日が通常状態となり、取得日は分析上の意味を持たないため置換した。

### DEC-027: 音声・全文文字起こしに保存期限と削除経路を設ける

- 状態: 採用
- 決定: 一時音声は処理完了後に削除する。全文文字起こしと正確なCodex入力本文は非公開内部データとし、作成日から365日を既定期限にする。30・90・180・365日・無期限の設定と手動削除を提供し、通常画面には必要最小限の根拠部分だけを表示する。
- 理由: 再現可能な分析に必要な内部証拠を保持しながら、権利・プライバシー・保存容量のリスクを抑えるため。

### DEC-028: 5～10分チェックポイントと実完了数の進捗を使う

- 状態: 採用
- 決定: 音声取得、分割文字起こし、話者割当、本人発言抽出、Codex分析、自動割当、ヒートマップ集計の順で処理し、5～10分単位で再開可能なチェックポイントを保存する。進捗は各段階の実完了数から算出する。
- 理由: ユーザー実施のCPUスモールテストでは40分級動画の文字起こし約74分、話者割当約4分、Codex分析約4.5分を要し、長時間処理の中断回復と正確な進捗把握が必要になったため。

### DEC-029: 現在値と追記専用監査ログを組み合わせる

- 状態: 採用
- 決定: 話者割当と同一分析scopeの正規化結果は現在値を1件だけ保持し、修正時に変更前・変更後の構造化JSON、理由、操作者、日時を追記専用監査ログへ保存する。全文文字起こしや正確なCodex入力本文は監査JSONへ複製しない。
- 理由: 通常検索を単純にし、修正前後を監査可能にしながら、全文データの重複と削除期限の迂回を防ぐため。
- 影響: 話者修正では依存分析をstaleにし、再分析成功後だけ現在結果を更新する。異なる基準日時の分析scopeは別々に保持する。

### DEC-030: 指数割当信頼度をCodexとアプリ規則の両方で検査する

- 状態: 採用
- 決定: 信頼度を `high`、`medium`、`low`、`unresolved` で保存する。Codex自己評価とは別に、本人の直接言及、周辺本人発言、競合市場、聞き手だけに存在する手掛かりをアプリ規則で検査し、異なる場合は低い側を自動採用上限にする。
- 理由: Codexの自己評価だけで誤った対象指数を高信頼として表示せず、同じ入力へ決定的なゲートを適用するため。
- 影響: `low` と `unresolved` は主ヒートマップへ自動採用せず、ユーザーの承認・修正・却下と理由を監査する。聞き手発言だけを根拠に `high` または `medium` にしない。

### DEC-031: 基準日時ごとの分析scopeを共存させる

- 状態: 採用
- 決定: 分析主体と選択日JST 23:59:59の組を一意なscopeとし、異なる基準日時の結果を共存させる。同じscopeの再分析は、検証成功後だけ現在結果を置換し、変更前後を監査する。
- 理由: ユーザーが年月日を選んで当時利用可能だった発言だけの予想を比較しながら、同じ日付の修正版を通常画面で単純に参照できるようにするため。

### DEC-032: 江守哲は固定YouTubeチャンネルIDだけを対象にする

- 状態: 採用
- 決定: 江守哲の収集・分析範囲はユーザーが指定する1つのYouTubeチャンネルに限定し、チャンネル表示名ではなく正規のYouTubeチャンネルIDを正本とする。動画URLから解決したチャンネルIDが固定IDと完全一致した場合だけ分析候補にする。
- 理由: チャンネル名の変更や同名チャンネルに影響されず、ユーザーが意図した発信元だけを安定して対象にするため。
- 影響: 対象の表示名は「江守哲の米国株投資チャンネル」と確認済みだが、正確なURLまたはIDは未提示なので表示名から推測せず、`configuration_required` として実装前に確認する。未設定時とID不一致時はフェイルクローズにする。他チャンネルの江守哲出演動画は手動URL登録でも `channel_out_of_scope` とし、動画単位の承認・修正では予想分析へ採用できない。採用範囲を変える場合はチャンネル方針自体を監査付きで変更する。
