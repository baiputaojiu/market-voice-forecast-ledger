# 公開データ方針

## 目的

開発作業の引き継ぎに必要な情報だけを公開GitHubリポジトリへ置き、認証情報、実データ、大容量データ、権利を確認できない情報を分離する。

## 公開する情報（Public Information）

- ソースコードと自動テスト。
- リポジトリスコープのCodexスキル。
- 公開安全検査などの開発スクリプト。
- 公開可能な設定例。値はダミーまたは空欄とする。
- 確定要件、重要な決定と理由、現在の計画、進捗要約、引き継ぎ情報。
- 権利と内容を確認済みの設計資料。
- 架空名と合成発言だけを使う最小サンプルデータ。

## 公開しない情報（Excluded Information）

- APIキー、アクセストークン、Cookie、パスワード、秘密鍵、Codex認証情報。
- 個人情報、PC固有の秘密情報、ユーザー名を含む絶対パス。
- YouTubeの動画、音声、字幕ファイル、大量の全文文字起こし。
- 本番SQLiteデータベース、journal、WAL、backup。
- 分析入力スナップショット、実発言を大量に含む中間・最終結果。
- 話者埋め込み、音声特徴量、基準音声クリップ。
- Whisper、pyannoteなどのモデル、重み、キャッシュ。
- `node_modules`、Python仮想環境、ビルド成果物、カバレッジ、一時ファイル、ログ。
- 公開権限を確認できない画像、文章、Stitch生生成物。
- 実在人物へデザイン確認用の架空発言や架空予想を割り当てた画面。

## ローカルデータの既定保存先（Default Local Data Location）

アプリが収集・生成する実データは、リポジトリ外の次の場所へ保存する。

```text
%LOCALAPPDATA%\MarketVoiceForecastLedger\
├─ db\
├─ transcripts\
├─ audio-temp\
├─ speaker-embeddings\
├─ analysis-snapshots\
├─ jobs\
└─ logs\
```

音声一時ファイルは処理後に原則削除する。削除失敗はジョブ状態へ記録し、次回の清掃対象にする。

## 公開前検査

保存スキルは、commit前に次を確認する。

1. `.gitignore` が禁止データ種別を覆っていること。
2. staged対象に秘密文字列、禁止拡張子、禁止ディレクトリ、大容量ファイルがないこと。
3. `git diff --cached` を確認し、今回と無関係な変更がないこと。
4. 実在人物へ架空の発言・予想を割り当てた公開用資料がないこと。
5. 検査失敗時はcommitとpushを行わず、対象を報告すること。

## 大きな節目のアーカイブ

通常のPC切り替えでは新規状態ファイルを作らない。要件の大規模改定やMVPリリースなど、現在文書から重要な前提を削除する必要がある節目だけ、削除前の情報がGit履歴だけでは発見しづらいと判断した場合に設計アーカイブを作る。作成理由と対象範囲を `decisions.md` に記録する。
